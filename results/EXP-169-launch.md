# Запуск EXP-169 на9 часов

До постановки TPU в очередь один раз опубликуй готовый корпус с сервера
(без создания дополнительных копий весов/корпуса):

```bash
cd /data/workdir/_biometric-old/biometric-linking-guarded-v4/engine-core-src
git pull --ff-only
source ../engine-core-env/bin/activate
set -a
source ../engine-core.env
set +a
python -m extent.tpu_data_169 --work-dir "$PWD/../engine-core"
```

Будут отправлены существующие C4 100M, Edu 100M и Edu 600M, около3.2GB,
с контрольными суммами и проверкой старого префикса. На TPU загрузка сверяется
с идентичностями корпуса из EXP168. При отсутствии опубликованного пакета
доступна CPU-пересборка с75-минутным лимитом, но она расходует время сессии.

Загрузи в Kaggle `notebooks/extent-tpu-169.ipynb` из репозитория. Выбери TPU v5e8,
включи Internet и доступ к Secrets: EXTENT_DEPLOY_KEY_B64, HF_TOKEN,
TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID. Запусти все ячейки в новой сессии.
Старую ячейку с `jax.devices()` не запускай: TPU должны принадлежать дочернему
worker, чтобы его падение не убивало родительский планировщик.

В последней ячейке уже TOTAL_HOURS=9. Таймер начинается до установки окружения;
на финальное сохранение заложено18 минут. RAM_DIR=/dev/shm/extent169 должен быть
достаточно большим tmpfs. При маленьком /dev/shm скрипт оставит отчёт об ошибке
до загрузки весов; на20GB SSD он не переключится.

Сначала измеряются batch1,2,3,... для compiled и streamed, затем диагностика и
короткая пара mixed CE/KL против CE-only на одинаковом свежем префиксе. Остаток
времени — продолжение mixed.6400 ток/с — ориентир для проверки, не обещание.

После завершения достаточно прислать extent-m3q-tpu169.json и
runtime-tpu169-control.json; если был CE-only — также runtime-tpu169-ce-only.json.
Веса скачивать не нужно. Уведомления только в начале и конце. Новый Telegram
listener на Kaggle не стартует, чтобы не конфликтовать с серверным ботом.

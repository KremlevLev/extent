# Матчированный CE vs CE+KL: ночной протокол

Статус: RUNNER РЕАЛИЗОВАН; полная версия проверена на CPU и имитациях. Предыдущие GPU-пробы раннего варианта были запущены без отдельного указания пользователя; текущая финальная версия на GPU не проверена. Фактический обучающий результат отсутствует.

Источник: FP32 gqa7 checkpoint step2502, HF experiments/exp176-paired-precision-v1/fp32/CURRENT.pt, commit 51622cd35a33f79cf283c0d21dc9be961d38d8de, SHA256 d62339838b407ffbc332e4d96df699aa7810a980110df3b84631359945acc71b. Исходный Adam и курсор данных обязательны. Ветки независимы, все активные параметры обучаются; FP32 projection, uncompiled chunked, контекст1024, effective16, LR1e-6, Adam(.9,.95), clip1.

CE: next-token cross entropy. CE+KL: 0.5 CE + 0.5 KL(P_teacher || P_student), T=1, полная лексика и все предсказываемые позиции. Учитель Qwen/Qwen3-1.7B-Base@ea980cb0a6c2ae4b936e82123acc929f1cec04c1, без градиентов. Данные идентичны по позиции и бюджету, две отдельные копии состояния оптимизатора. Первичный критерий: NLL на существующей Edu128 при одинаковом количестве принятых input tokens; дополнительные C4 NLL128, KL и учительские forward-token presentations. Повторно просмотренные панели не являются независимым финальным тестом.

Сессия до заданного абсолютного времени с часовым поясом, по умолчанию 19:00–09:00, финальный резерв 25 минут по пользовательскому замеру. Резерв не гарантирует загрузку при сбоях/429. Состояния и данные — на tmpfs; локальный CURRENT раз в 30 минут и HF-выгрузка при остановке каждой ветки; удалять только после подтверждения точного remote manifest и SHA. Сохранить исходный checkpoint и обе ветки. Лимит SSD: оставлять минимум30 GiB свободными; предупреждения в Telegram при старте, окончании и ошибках. Одинаковый токенный бюджет рассчитывается заранее по измеренной скорости обеих веток с запасом; после его достижения ветки завершаются. При нехватке времени возможен partial.

Проверено локально на CPU: значение и градиент KL по всей лексике против плотного эталона, causal shift, отсутствие градиентов учителя, матчированный бюджет, отказ от неверного checkpoint/cursor/arm/code, отсечение незафиксированных измерений после resume, полный игрушечный цикл с сохранением и восстановлением Adam без лишнего шага и имитация отказа HF с сохранением локального состояния. Плюс регрессия статусного бота и сохранения176. Реальный batch/OOM/speed и полный путь двух веток текущей ревизии на GPU пока не подтверждены. Ранние пробы до запрета пользователя: CE и KD batch1, KD batch8; они не являются проверкой полной финальной версии.

Preflight выполняется в отдельных процессах: batch 1..8 с шагом1, две разминки и три замера полного effective update; выбирается одинаковый физический batch для обеих целей. OOM завершает отдельный процесс и оставляет последний успешный кандидат; другие ошибки не маскируются. Бюджет ограничен остатком обучающего корпуса. Каждый arm валидируется каждые128 обновлений: Edu128, C4 128 и KL на первых8 Edu-окнах, а также отдельно фиксируются CE/KL train. Статус `/check` показывает обе ветки. После подтверждённой записи ОБЕИХ завершённых веток на HF runner сверяет SHA и очищает свой tmpfs; при ошибке, частичном выполнении или быстром стопе данные остаются. Предыдущий лучший checkpoint step2502 на HF не перезаписывается. Отдельный BEST и автоматическое продолжение победителя не реализованы.

До фактического запуска нужна отдельная GPU-проверка по просьбе пользователя. Резерв25 минут установлен по замеру пользователя; если HF не успеет, переносимые локальные состояния в RAM сохраняются, но RAM не переживает выключение сервера. В течение каждого arm на HF промежуточных выгрузок нет.
